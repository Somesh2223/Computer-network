Joint Semantic Error Protection and State Supersession · VIT BCSE308P

Recover a lost value only if it is still worth something.

A drone streams its state to the ground over a lossy link. When a packet is lost, this protocol checks every field inside it, one by one, and resends only what the receiver still needs.

Every field in a lost packet gets one verdict
SUPERSEDED

A newer copy was already sent. The lost one is obsolete, so it is skipped.

WITHIN TOLERANCE

The field updates faster than the app's deadline. The next value will arrive in time.

REPAIR

It is still the newest value and the app needs it. Only that field is resent.

If nothing needs repairing, a 5-byte SKIP closes the gap.

Where the line falls

A repair helps only if the field updates more slowly than τ + H + R

A NACK reaches the sender exactly τ + H + R after a loss. Any field due sooner has already been resent by then, so the check "was it resent?" enforces this line without ever computing it. Move the sliders.

Crossover T*

Measured: the knee sits where the model said

A two-field probe: a filler at tick rate exposes losses while the probe's period is swept. At 5% loss the benefit stays at most 0.12% of a period below T*, then climbs. At 20% loss, losses in a row give some benefit below it, which the first-order model ignores.

How it is built

One protocol codebase, run three ways

The receiver only reports gaps. The sender decides, because only its send log knows what a lost packet held and what has gone out since.

Simulator

Real packet encoding, simulated clock and link. Deterministic, so every number above reproduces exactly.

Real UDP sockets

The same sender and receiver code as two processes. On seed 11 it reproduces the simulator's losses and bytes exactly, with about 2 ms extra staleness.

Linux kernel and netem

Two network namespaces on a veth pair with tc/netem delay and loss, against the kernel's own TCP.

Checked

26 tests pass. Zero false suppressions in every simulated and real run, re-derived from the raw transmission log.
